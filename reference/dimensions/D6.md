# D6: Security and AI Supply Chain

[All dimensions](README.md) · [Reference guide](../framework-v2.md)

**Why it matters:** OWASP lists prompt injection (LLM01:2025), supply chain (LLM03:2025) and excessive agency (LLM06:2025) among the top risks [38], and agent goal hijack (ASI01) first for agentic applications [39]; NIST SP 800-218A adds practices for AI model development to the SSDF [40].

**Strategies:** S7 Security & Governance, S6 Agentic Activation · **Report group:** G3 (Secure, deliver and foundations)

How to use this page: agree the current level of each question with its evidence, then plan the next step from the L3 anchor (or the L4 anchor when L3 already holds).

## Questions

### D6-Q1: Baseline scanning on every repository

> Are code scanning (SAST), secret scanning with push protection, and dependency review applied to all repositories, including agent branches?

- **L3:** Enabled by default for all new and most existing repositories; push protection applies to every commit, human or agent; alerts have owners and service-level targets.
- **L4:** Coverage is near complete and verified automatically; mean time to remediate is tracked.
- **Evidence examples:** Security coverage dashboard, remediation time.
- **Basis:** [7] [13] [40] [52]

### D6-Q2: AI-assisted remediation

> Is AI-assisted remediation (for example autofix for code scanning) used to fix vulnerabilities, with fixes reviewed and tested before merge?

- **L3:** Autofix suggestions are enabled for most repositories; acceptance and reopen rates are tracked.
- **L4:** Security campaigns use AI remediation at scale, and remediation time is reported to leadership.
- **Evidence examples:** Autofix settings, remediation metrics.
- **Basis:** [13] [57]

### D6-Q3: Prompt injection defenses for agents

> Are agents protected against prompt injection and goal hijack (untrusted content treated as data, hidden instructions filtered, network egress restricted)?

- **L3:** Agent firewalls and egress restrictions are kept on; guidance tells teams which content sources are untrusted.
- **L4:** Agents are red-teamed regularly against OWASP LLM01:2025 and ASI01 scenarios; findings are tracked to closure.
- **Evidence examples:** Firewall configuration, red-team reports.
- **Basis:** [7] [38] [39]

### D6-Q4: Least privilege for agents

> Do agents run with least privilege (scoped tokens, no production secrets, restricted branches, sandboxed environments)?

- **L3:** Agent permissions are documented and reviewed; agents cannot reach production credentials or push to protected branches.
- **L4:** Permissions are just-in-time and time-bound; access is reviewed automatically.
- **Evidence examples:** Agent environment configuration, token scopes, access reviews.
- **Basis:** [7] [19] [38] [39]

### D6-Q5: AI supply chain

> Are models, MCP servers, IDE extensions and agent tools vetted before use, with provenance and SBOMs for what you build and ship?

- **L3:** A review process covers AI components; SBOMs and build provenance are produced for most builds.
- **L4:** Provenance is verified at deployment (for example SLSA level targets); unvetted components are blocked automatically.
- **Evidence examples:** Component review records, SBOM and attestation samples.
- **Basis:** [38] [40] [43] [52]

### D6-Q6: Threat modeling for AI features and agents

> Are AI features and agentic workflows threat-modeled with AI-specific risks (OWASP LLM and Agentic Top 10, NIST SP 800-218A)?

- **L3:** Threat models are required for new AI features and agent workflows and reviewed by security.
- **L4:** Threat models are updated after incidents and red-team exercises; controls are verified by automated tests.
- **Evidence examples:** Threat model documents, security review records.
- **Basis:** [38] [39] [40]

### D6-Q7: Audit trail for agent actions

> Are agent sessions and actions (prompts, tool calls, commits, approvals) logged, attributable to an identity, and retained according to policy?

- **L3:** Agent activity is logged centrally and linked to the requesting user and the agent identity.
- **L4:** Logs feed anomaly detection; audits can reconstruct any agent change end to end.
- **Evidence examples:** Audit log configuration, sample investigation.
- **Basis:** [7] [19]
